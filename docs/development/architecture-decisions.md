# 架构决策记录

> 创建时间：2026-02-16
> 状态：持续更新

本文档记录 Unicodex 项目在开发过程中的重要架构决策，确保项目知识持久化，便于后续开发者（人类和 LLM）理解设计意图。

## ADR-001: 依赖方向 — Core 依赖模块，而非模块依赖 Core

**日期**：2026-02-16
**状态**：已决定

**背景**：
最初考虑让所有 `ucx-*` 模块依赖 `unicodex-core`，由 core 提供公共类型。但这会导致循环依赖问题，并且限制了第三方阅读器只引用部分模块的能力。

**决定**：
`unicodex-core` 仅作为 CLI 入口，**依赖**所有 `ucx-*` 功能模块，而非被依赖。

```
unicodex-core (CLI 入口)
  ├── 依赖 ucx-init
  ├── 依赖 ucx-build
  ├── 依赖 ucx-parse
  ├── 依赖 ucx-verify
  ├── 依赖 ucx-sign
  ├── 依赖 ucx-version
  └── 依赖 ucx-crypto
```

**好处**：
- 第三方阅读器可按需引用：仅 `ucx-parse` + `ucx-verify` + `ucx-crypto` 即可完整支持 UCX 文件读取
- 功能模块之间可按需互相依赖（如 `ucx-build` 依赖 `ucx-sign` 实现构建时自动签名）
- 避免不必要的编译依赖

**影响**：
- 公共类型（如 UCX ID、Manifest 结构）需要放在被多个模块共同依赖的位置
- 考虑未来抽取 `ucx-types` 或 `ucx-common` 公共类型 crate

## ADR-002: ucx-build 与 ucx-parse 分离

**日期**：2026-02-16
**状态**：已决定

**背景**：
最初 `ucx-build` 同时承担打包和解包职责。但"构建"和"解析"是两个完全不同的操作方向。

**决定**：
将解析读取功能拆分到独立的 `ucx-parse` 模块：
- `ucx-build`：负责打包构建 UCX 文件（作者/出版方使用）
- `ucx-parse`：负责解析读取 UCX 文件（阅读器/验证工具使用）

**好处**：
- 阅读器只需引用 `ucx-parse`，无需编译构建相关代码
- 职责单一，降低模块复杂度

## ADR-003: 使用 git2 (libgit2) 而非 Git CLI

**日期**：2026-02-16
**状态**：已决定

**背景**：
`ucx version auto` 需要检测文件变更来自动生成版本号。有三种方案：
1. 调用系统 `git` 命令
2. 使用 `git2` crate（libgit2 Rust 绑定）
3. 自实现 diff

**决定**：
使用 `git2` crate。

**理由**：
- 无需系统安装 Git，降低用户环境依赖
- 纯 Rust 调用，跨平台行为一致
- 可嵌入为库使用
- 回退方案：无 Git 仓库时使用 `.ucx-snapshot.json` 文件哈希快照

## ADR-004: 加密在签名之前

**日期**：2026-02-16
**状态**：已决定

**背景**：
加密和签名的顺序影响验证流程。

**决定**：
加密在签名之前执行（Encrypt-then-Sign）。

**流程**：
1. 准备明文文件
2. 按配置加密 → 得到密文
3. 对密文计算哈希 → 生成 MANIFEST.MF
4. 对 MANIFEST.MF 签名

**好处**：
- 无需解密即可验证文件完整性（签名保护密文）
- 篡改密文 → 签名验证失败
- 替换密文 → 哈希不匹配

## ADR-005: 版本语义推荐 卷.章.修订

**日期**：2026-02-16
**状态**：已决定

**背景**：
小说作品的版本号需求与软件不同。传统 SemVer 的 MAJOR.MINOR.PATCH 对小说场景不够直观。

**决定**：
推荐（非强制）`X.Y.Z` = `卷号.章节数.修订号`：
- `X`：当前卷数
- `Y`：当前卷内最新章节编号
- `Z`：修正计数，Z 初始值为 0，发布新章节时归零

作者也可选择 SemVer 或其他自定义语义，UCX 不强制约束。
