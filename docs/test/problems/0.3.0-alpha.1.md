## 发现的问题

### BUG-001: `sign` 时未校验密钥与证书是否匹配

- **严重程度**：高
- **现象**：使用 key1 + cert2（不匹配的密钥与证书）可以成功完成签名
- **影响**：签名后 verify 显示 Layer 1 FAIL，但用户可能未注意
- **根因位置**：`ucx-sign/src/lib.rs` 的 `sign()` 函数
- **建议修复**：在签名前验证 signing_key 对应的 verifying_key 与证书中的公钥一致

### BUG-002: `keygen` 静默覆盖已有密钥文件

- **严重程度**：中
- **现象**：连续两次 `ucx keygen --output same.key` 无警告覆盖
- **影响**：用户可能意外丢失已有密钥
- **根因位置**：`ucx-sign/src/lib.rs` 的 `keygen()` 函数
- **建议修复**：检查文件是否已存在，若存在则报错提示使用 `--force`

### BUG-003: `cert create --days 0` 可创建 0 天有效期证书

- **严重程度**：中
- **现象**：0 天有效期证书可正常创建，签名和验证均通过
- **影响**：verify 不检查证书有效期，可能导致使用已过期证书签名
- **根因位置**：`ucx-sign/src/cert.rs` 和 `ucx-verify/src/lib.rs`
- **建议修复**：`cert create` 拒绝 days=0；verify 时检查证书有效期并在过期时警告

### UX-001: verify 对 INVALID/PARTIAL 返回 exit code 0

- **严重程度**：低
- **现象**：签名验证失败（INVALID/PARTIAL）时退出码仍为 0
- **影响**：脚本无法通过退出码判断验证结果
- **根因位置**：`unicodex-core/src/main.rs` 的 Verify 命令处理
- **建议修复**：INVALID 返回 exit code 1，PARTIAL 返回 exit code 2

### NOTE-001: 多签名者场景中 Layer 2 仅最后签名者有效

- **严重程度**：信息（设计限制）
- **现象**：第二次签名修改了 archive，导致第一个签名者的 Layer 2 验证失败
- **原因**：Layer 2 对整个 ZIP 签名，后续签名修改了 ZIP 结构
- **评估**：符合 APK v2 签名的设计特性，非 bug。未来可考虑多签名者共享同一个签名块。
