## 一、回归验证结果

> 以下为 v0.1.0-alpha.1 报告中 8 项"✅ 已修复"标注的逐项回归验证。

### P-001 [严重] BLAKE3-Digest 编码格式 ✅ 验证通过

**原始问题**：MANIFEST.MF 中 BLAKE3-Digest 使用 Hex 编码（64 字符），规范要求 Base64。

**验证方法**：构建项目后解压 UCX 文件，检查 MANIFEST.MF 中 Digest 值的编码格式。

**验证结果**：Digest 值现为 44 字符的 Base64 编码（含 `=` padding），可正确解码为 32 字节。

```
BLAKE3-Digest: g8cMyIZMdo0GMzqGiUJceBHqitmCoEc6MR0JcQRK7MI=
BLAKE3-Digest: xGaYg/DlgfyI3kL2YWW9Ayr9M7vvib3upxHsYWZ+nSM=
BLAKE3-Digest: OE+/gW6uZYF3U9UaDTmVSyFv9mODvQkDvz5oLFXNVGM=
```

- 长度：44 字符 ✅
- 末尾 `=` padding ✅
- Base64 解码后为 32 字节（BLAKE3 256-bit） ✅

### P-005 [中等] struct.json file/children 互斥校验 ✅ 验证通过

**原始问题**：节点同时包含 `file` 和 `children` 时 `ucx build` 无报错。

**验证方法**：手动构造违规 struct.json，执行 `ucx build`。

**测试用例**：
```json
{
  "structure": [{
    "title": "both_present",
    "file": "chapter-001.md",
    "children": [{"title": "sub", "file": "chapter-001.md"}]
  }]
}
```

**验证结果**：构建正确终止，exit code 1，错误信息清晰引用规范条目。

```
Error: invalid project structure: node 'both_present' has both 'file' and 'children'
— they are mutually exclusive per spec §4.1
```

**验证方法**：struct.json 中引用 `nonexistent.md`，执行 `ucx build`。

## 二、新发现问题

### NEW-001 [低] name/author 字段接受换行符，导致 TOML 生成多行字符串 ✅ 已修复

**发现来源**：SEC-003 回归验证中发现。

**复现步骤**：
```bash
ucx init ./test -n "title" -a $'author\nnewline'
```

**实际行为**：命令成功执行（exit code 0），生成的 `unicodex.toml` 中出现多行字符串：

```toml
[[creators]]
name = """
author
newline"""
role = "author"
```

**影响**：
1. 作者名和书名中包含换行符不是合理输入
2. TOML 序列化为多行字符串（`"""`），虽然语法正确，但语义不合理
3. 后续转换为 codex.json 时，`name` 值将包含 `\n`，可能影响阅读器的 UI 渲染

**建议**：对 `--name` 和 `--author` 参数额外拦截 LF (`\x0A`) 和 CR (`\x0D`)。TAB (`\x09`) 可保留放行或视具体需求决定。

---

### NEW-002 [信息] `ucx build` 在 P-006 场景下仍输出带时间戳的 WARN 日志 ✅ 已修复

**发现来源**：P-006 回归验证中发现。

**实际行为**：

```
[2m2026-02-16T11:18:04.549875Z[0m [33m WARN[0m [2mucx_build[0m[2m:[0m Referenced file not found: content/nonexistent.md
Error: invalid project structure: struct.json references 1 missing file(s): nonexistent.md
```

WARN 日志行包含 ANSI 转义序列和时间戳（`2026-02-16T11:18:04.549875Z`），而 Error 行则是简洁格式。UX-004 的修复统一了 `ucx init` 的默认输出为简洁格式，但 `ucx build` 的 WARN 级别日志仍保留了 `tracing` 框架的完整格式。

**影响**：用户面对混合格式的输出（带时间戳的 WARN + 简洁的 Error），体验不一致。

**建议**：WARN 日志也应使用简洁格式输出，或者将此信息合并到 Error 消息中（当前 Error 消息已包含足够信息，WARN 行可移除）。
